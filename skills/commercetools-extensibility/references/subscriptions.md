# Change Subscription vs Message Subscription

### When to use message vs change subscription and what are the differences.

Reference documentation:
- https://docs.commercetools.com/api/projects/subscriptions#changesubscription
- https://docs.commercetools.com/api/projects/subscriptions#messagesubscription

---

## ChangeSubscription

I will use customer as an example to illustrate how it works, however this applies to most other commercetools entities. To subscribe to changes, the API call will look as follows:

```
POST {{host}}/{{project-key}}/subscriptions
```

```json
{
  "destination": {
    "type": "SQS",
    "queueUrl": "<url-to-my-queue>",
    "authenticationMode": "IAM",
    "region": "<my-region>"
  },
  "changes": [
    {
      "resourceTypeId": "customer"
    }
  ],
  "key": "test-queue"
}
```

This subscription will trigger a message every time a customer is changed (every change, including changes to custom fields). The message will not contain specific information about the actual change, it will provide the id and version of the resource (customer in this case) that has been changed.

Here is an example of such message (generated by modifying a custom field):

```json
{
  "notificationType": "ResourceUpdated",
  "projectKey": "YOUR_PROJECT_KEY",
  "resource": {
    "typeId": "customer",
    "id": "PRODUCT_ID"
  },
  "resourceUserProvidedIdentifiers": {
    "key": "customer-import-resource-key",
    "customerNumber": "4",
    "externalId": "external-id-123"
  },
  "version": 15,
  "oldVersion": 14,
  "modifiedAt": "2023-02-01T19:19:03.918Z"
}
```

## Message Subscription

These are subscriptions to specific events, for example product published or customer password updated. Subscription to specific messages; the call to create such subscription looks as follows:

```json
{
  "destination": {
    "type": "SQS",
    "queueUrl": "<url-to-my-queue>",
    "authenticationMode": "IAM",
    "region": "<my-region>"
  },
  "messages": [
    {
      "resourceTypeId": "customer",
      "types": ["customerFirstNameSet", "customerPasswordUpdated"]
    }
  ],
  "key": "test-queue"
}
```

In this case a message will be triggered if any of the 2 actions configured happen. Leaving the actions empty will trigger a message for all supported actions for the entity (in the example customers).

If this option is used the message will provide information about the change. Here is an example when a customer address is modified:

```json
{
  "notificationType": "Message",
  "projectKey": "dario-project-1",
  "id": "2c3e6adf-8945-4fbf-ba5f-e829b724ce4f",
  "version": 1,
  "sequenceNumber": 8,
  "resource": {
    "typeId": "customer",
    "id": "111ae6f0-0d17-4d07-b479-50c7d020e355"
  },
  "resourceVersion": 17,
  "resourceUserProvidedIdentifiers": {
    "key": "customer-import-resource-key",
    "customerNumber": "4",
    "externalId": "external-id-123"
  },
  "type": "CustomerAddressChanged",
  "address": {
    "id": "3PVYzz6y",
    "firstName": "Alice",
    "country": "DE",
    "building": "5",
    "key": "wCVKP6iU",
    "custom": {
      "type": {
        "typeId": "type",
        "id": "271c0464-623a-4688-8afe-77d984e1babb"
      },
      "fields": {
        "add-field-1": "New value for custom Field"
      }
    }
  },
  "createdAt": "2023-02-01T19:29:27.715Z",
  "lastModifiedAt": "2023-02-01T19:29:27.715Z"
}
```

**Important limitation:** Message subscriptions only support a predefined set of actions that will trigger a message; other changes to the resource will not. For example, changes to a product attribute will not trigger a message.
